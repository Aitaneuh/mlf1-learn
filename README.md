# MLF1 Learn

A self-hosted, progressive learning site for **BTI1041 Machine Learning Foundations 1** (BFH).
Short lessons, interactive graphics, Python exercises that run **in the browser** (Pyodide: NumPy, pandas,
scikit-learn, matplotlib) with automatic checking, unit exams that unlock the next unit, and hands-on projects.
Progress (lessons, exam scores, your code) is stored per user in SQLite.

- 13 units (course weeks 1–10 + Python prerequisite + final review), 41 lessons/exams, 6 projects
- 112 auto-checked exercises, 44 runnable code cells, 58 quizzes/exams, 15 interactive visualisations
- Zero runtime dependencies: a single Node.js process (built-in `node:sqlite`) serves everything

> The explanations are written for this site; they follow the structure of the course but do not reproduce
> the official slides. Datasets in `public/data/` are public datasets (Iris, Pendigits, MNIST sample,
> 20 Newsgroups subset, Montréal bike counts) plus small synthetic files generated by `scripts/prepare_data.py`.

## Deploy with Portainer (stack from Git)

1. Portainer → **Stacks** → **Add stack** → **Repository**.
2. Repository URL: `https://github.com/<you>/mlf1-learn`, reference `refs/heads/main`, compose path `docker-compose.yml`.
3. Optional environment variables:
   | variable | default | meaning |
   |---|---|---|
   | `MLF1_PORT` | `8090` | host port |
   | `ALLOW_SIGNUP` | `true` | set to `false` after creating your account (the first account can always be created) |
   | `COOKIE_SECURE` | `false` | set to `true` when served over HTTPS behind a reverse proxy |
4. Enable **GitOps updates** (polling, e.g. every 5 minutes, or a webhook) with **re-build / force redeployment**,
   so every `git push` with new course content is deployed automatically.
5. Deploy, open `http://<server>:8090`, create your account.

Progress lives in the named volume `mlf1-data` (`/data/mlf1.db`) and survives redeploys.

## Run locally

```bash
node --version            # needs >= 22.13
npm start                 # http://localhost:3000  (data in ./data)
# or
docker compose up --build
```

## Content format

Everything lives in `content/`:

- `course.json` — units and items (lesson / exam / project), order, unlock flow, “What's new” entries
- `lessons/`, `exams/`, `projects/` — Markdown with KaTeX math (`$...$`, `$$...$$`) and custom blocks:

````text
:::exercise id=unique-id title="Title"
--- task
Markdown task text
--- setup
hidden Python run before the learner's code
--- starter
code shown in the editor
--- check
hidden Python with asserts (variables of the learner's code are available; printed output is in __stdout__)
--- hint
first hint (repeat `--- hint` for more)
--- solution
reference solution
:::

:::quiz
? Question text
- wrong option
+ correct option (several + = multi-select)
> Explanation shown after answering
? Numeric question
= 0.75 tol=0.01
:::

:::code            runnable cell (not graded)
:::viz name=gd1d   interactive graphic (see public/js/viz.js)
:::note / :::tip / :::warn / :::key / :::exam   callouts
:::reveal title="..."   click-to-reveal answer
````

Data files referenced as `data/<file>` (or the JupyterHub path `~/bfh-datasets/bti1041-mlf1/<file>`) are loaded
automatically into the in-browser Python.

## Validate content

Every exercise's solution must pass its check, and the starter code must not:

```bash
npm i --no-save pyodide@0.29.4
npm run validate            # or: node scripts/validate-content.mjs u4   (filter by item id)
```
