? Why can exactly the same Python code behave differently on two machines?
+ Because the environment differs: Python version, package versions, working directory, OS, system libraries…
- Because Python is random
- It cannot; identical code always gives identical results
> Code depends on every layer of the stack below it.

- The whole operating system
- The hardware
> It isolates only part of the stack.

? Which statement about the Jupyter kernel is correct?
+ It is the process that executes code and stores variables in memory
- It is the .ipynb file
- It is the browser tab
> The notebook is only the frontend.

? Cells on the page are A (`x = 1`), B (`x = x + 10`), C (`print(x)`). You run A, B, B, C. What is printed?
= 21
> Order of execution matters: 1 → 11 → 21.

? You delete the cell `secret = 42` after running it. Then you run `print(secret)` without restarting. What happens?
+ It prints 42, because the variable is still in the kernel's memory
- NameError
- It prints None
> Deleting code does not delete the variable from memory — until the kernel restarts.

? What is the best evidence that a notebook is reproducible?
- It worked when I clicked through the cells
+ It runs without errors after Kernel → Restart & Run All
- It has been saved
> A fresh kernel, top to bottom, removes hidden state.

? Installing vs importing: which is correct?
+ Installing puts a package into an environment once; importing loads it into the current session
- Importing downloads the package from the internet
- They are the same
> You install once per environment, import in every session.

? `FileNotFoundError: data/customers.csv`. What do you inspect first?
- `df.columns`
+ The working directory (`os.getcwd()`) and the files visible from it
- The pandas version
> Relative paths start at the working directory.

? Code runs without errors but selects all 8 customers instead of the 5 active ones. What kind of bug is it?
- An environment problem
+ A logic/data problem — only found by inspecting values and counts
- A kernel crash
> Silent bugs need checks against expectations.
